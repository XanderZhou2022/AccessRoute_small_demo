04 · Get started

Start the demo

First-time setup

  1. Install Node.js 22 LTS or newer on Windows or macOS.
  2. Extract the project folder. Open a terminal in that folder.
  3. Install dependencies and start the local demo:
npm ci
npm run dev
  1. Open http://127.0.0.1:5173/map-demo/index.html in a modern browser. Keep the terminal running while using the demo.

On later visits, run npm run dev and reopen the address. Stop the demo with Ctrl+C in the terminal.

Optional: enable Qwen-powered assistance

Route planning works without an AI key. To enable the Qwen workflows, copy .env.example to .env, set your private DASHSCOPE_API_KEY in that local file, then restart the demo. Never paste the key into the browser or share it in screenshots.

DASHSCOPE_API_KEY=your_private_key
Production build: for the locally served production build, run npm run build, then npm start and open http://127.0.0.1:8787/map-demo/index.html.
05 · Plan a route

Choose places and travel needs

  1. Select the place pill at the top of the map, choose a departure and destination, then apply the selection.
  2. Expand the bottom sheet and choose a profile: walking, wheelchair, elderly, stroller or heavy luggage. Adjust the available route preferences as needed.
  3. Select Search route at the bottom of the screen.
  4. Compare the sheltered and shorter route options, review their limitations, then select Start navigation.

Compare map views

Use the overview map for the surrounding route and the floor-navigation view for indoor floor geometry. Use the floor controls and map zoom controls to inspect a level. Follow the displayed route segments, but treat every path as a demo unless verified independently.

Unknown is not accessible: source data can describe geometry without confirming door widths, gradients, operating hours, permission to pass or lift service. Even “verified routes only” does not certify the remaining route.
06 · Navigate and request help

Follow steps and handle a demo closure

  1. Start the navigation demonstration from the route preview.
  2. Read the current instruction and inspect the corresponding map segment or floor.
  3. Advance a step using the on-screen control after you have checked your surroundings. Progress is user-operated; it is not live indoor positioning.
  4. In the elevator-event demo, simulate a lift outage to see the remaining route recalculate. Restore the lift or reset the journey when finished.

Optional AI help

Use the ? help control for facility or location assistance. Travel preferences are entered in the planning sheet. Depending on the workflow, Qwen requires a configured backend; review any proposed match or route change before applying it:

  • Travel preferences: describe needs in text and review the suggested preference changes before applying them.
  • Photo obstacle report: submit a photo and review the proposed facility/candidate before applying an event or reroute.
  • Photo location help: review matched place candidates and confirm the right one before changing the route start.
  • Voice guidance: request the next instruction; browser speech output depends on the device's installed language voice.
07 · Accessibility, weather and boundaries

Use the interface accessibly

  • Use the skip link and keyboard focus outline to move through the main screen without starting at every control.
  • Use browser/device text scaling, high contrast and reduced motion where available. Some demo screens also expose larger text or touch-target presentation.
  • For voice output, enable a Cantonese (Hong Kong) voice in the operating system if available. Actual microphone recognition and speech output are device/browser dependent.

Weather information

When the backend is running and weather data is available, the app can show Hong Kong Observatory observations, forecast and warning data. Check its live/stale indicator and update time. Territory-wide readings may not reflect conditions at your current street or building.

Known limits

Location and navigation
  • No continuous real-time indoor positioning.
  • Step progress is advanced by the user.
  • Map coverage is limited to the demo scenes.
Accessibility and transit
  • Many access attributes remain unknown and need field verification.
  • Lift status is simulated, not a live feed.
  • Saved MTR connections are not live schedules, fares or accessibility data.
AI and photos
  • AI needs a configured backend key and network access.
  • Recognition and provider behavior have not been certified in real-world use.
  • Always review and confirm proposed candidates.
Accounts and service
  • Settings may be stored only in the local browser.
  • Session/operator functions are for the local demo, not a production service.
  • Accessibility checks do not equal WCAG certification.
Safety note: AccessRoute HK is a research demonstration, not certified real-world accessibility navigation. Confirm route conditions, public access, station facilities, lift availability and safety information before travelling. If in doubt, use a verified alternative or ask the venue/operator for assistance.
