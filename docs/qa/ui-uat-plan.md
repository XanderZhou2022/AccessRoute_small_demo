# AccessRoute HK UI 使用者驗收測試計劃

## 1. 目的與範圍

確認使用者能否在桌面及手機瀏覽器中完成主要介面旅程：選擇地點、設定出行需要、比較目前可計算的路線、閱讀並推進導航，以及使用求助和配對操作員介面。測試也會檢視鍵盤、放大顯示及螢幕閱讀器的關鍵操作。

這是產品 UI UAT，不是 WCAG 認證或正式安全驗證。UAT 不得把演示資料、模擬結果或未核實的通道描述成真實、已認證的無障礙服務。

### 納入範圍

- 地點選擇、起終點交換及輸入錯誤處理。
- 輪椅、長者、重物、升降機／樓梯偏好、坡度、路線目標及步速設定。
- 可用路線顯示、不可行路線阻擋、導航文字及步驟推進。
- 天氣提示、GPS 同意提示、語音輸入／播報的可用與不可用情況。
- 照片求助及迷路定位的本機／模擬互動、使用者同意和明確失敗狀態。
- 操作員配對、步驟同步、設施停用／恢復及重新規劃。
- 手機版版面、鍵盤焦點、放大文字及輔助科技基本操作。

### 不作為本輪通過條件

- 九龍塘室外、Mall A、Mall B 手冊專屬路線：依使用者決定暫緩，不能測成可導航功能。
- 真實 AI 成功率、Street View、即時港鐵班次／車站設施、室內定位、真實地圖通行狀態及正式環境登入：依賴外部資料或服務，需另外安排整合／現場驗收。
- WCAG 2.0/2.1/3.0 整體符合性：UAT 發現不代表認證；需另外做完整技術稽核。

## 2. 測試環境與角色

### 本機環境

- 啟動：在專案根目錄執行 `npm run dev`。
- UI：`http://127.0.0.1:5173/`（預設開啟地圖卡片式旅程介面）。
- API：`http://127.0.0.1:8787/`。
- 地圖優先介面：`http://127.0.0.1:5173/map-demo/index.html`。
- 舊版完整規劃工作台（比較／除錯用）：`http://127.0.0.1:5173/?legacy=1`。
- 離線案例：`http://127.0.0.1:5173/?demo=1`。
- 每次測試前確認前端與 `/api/health` 均回應 HTTP 200；本機服務只供可信任的測試使用。

### 建議測試者

1. 產品負責人：確認工作流程、用詞、限制提示與驗收結果。
2. 輪椅使用者或熟悉輪椅出行的代表：檢查需求設定和路線資訊是否易理解；不要求實際使用未核實路線出行。
3. 長者／低視力／認知或手部操作需求代表：檢查文字、按鈕、步驟清晰度及觸控操作。
4. 鍵盤與螢幕閱讀器測試者：使用 VoiceOver（macOS/iOS）或 TalkBack（Android）完成關鍵任務。
5. 測試記錄員：逐項記錄結果、裝置、瀏覽器、縮放比例、截圖／錄影（先取得參與者同意）及缺陷編號。

使用者代表可拒絕任何任務或中止測試；不可要求參與者把研究演示當作實際出行指引。

## 3. 測試前準備

- 桌面 Chrome 或 Safari 最新穩定版；iPhone Safari 與 Android Chrome 各一部實機（可用時）。
- 桌面寬度 1280px、手機 390px；另測 200% 瀏覽器縮放及手機大字設定。
- 清除 `accessroute-map-demo` 本機儲存或使用無痕視窗；確認起終點預設為 PopCorn 2 → 又一城／九龍塘站。
- 關閉真實定位權限作「拒絕」測試；另在明確同意下做定位允許測試。不得保存或外傳參與者真實 GPS。
- 確認演示操作員頁可用；使用測試行程，不使用真實用戶資料。
- 真實模型供應商未設定時，按「服務未設定」情境測錯誤與回退，不將模擬回應算作模型驗收。
- 測試照片只用獲准、無個人資料的樣本；不得上傳參與者或旁人的照片。

## 5. 無障礙檢查清單

- 焦點順序跟隨畫面與任務邏輯；焦點可見且不被 sticky／浮動元件遮住。
- 每個互動元件可用鍵盤操作；不以顏色作唯一狀態表示。
- 對話框可進入、操作、關閉並把焦點還給開啟元件；Escape 行為須在目標瀏覽器實測。
- 螢幕閱讀器可辨識地標、標題層級、表單 label、必填／錯誤、按鈕用途及即時狀態。
- 文字對比度、非文字控制邊界、焦點框及路線色彩以工具和人工雙重檢查；地圖顏色須有文字標籤／圖例。
- 200% 縮放、窄螢幕、大字與減少動態效果下仍可完成任務。
- GPS、照片、語音及模型資料傳送前有明確同意與用途說明。
- 測試者可在任何時候停止；不安排真實場地無障礙路線試走作為本 UAT 前提。

## 6. 缺陷嚴重程度與通過門檻

- **S0 阻斷／安全**：可能把無效路線呈現為可安全通行、阻止使用者求助／停止，或私自傳送敏感資料。立即停止相關驗收，必須修正後重測。
- **S1 嚴重**：核心任務不可完成；鍵盤／螢幕閱讀器無法完成關鍵旅程；錯誤或設施故障被隱藏。發布前必須修正或由產品負責人明確延後該功能。
- **S2 一般**：有可用替代操作，但資訊、焦點、響應式版面或狀態提示不理想。建立修正期限及負責人。
- **S3 輕微**：不影響任務完成的文案或視覺問題。記錄並排入後續。

UAT 建議通過條件：

1. 所有 Must-have 案例（UAT-01 至 08、11、13 至 17）均通過；外部服務案例可標明受阻，但不可報為通過。
2. 沒有未解決的 S0／S1。
3. 關鍵任務可由目標使用者在所選桌面及手機配置完成。
4. 所有受阻、mock、手動替代及資料限制均在驗收紀錄中清楚標記。
5. 產品負責人、測試代表和工程負責人記錄簽核日期及已接受的剩餘風險。
